# プロダクト定義

## 1. 目的

WSL Ubuntu の開発環境設定を、**編集の往復が素朴に効く形（ホーム側の編集が Git 差分になり、`git pull` がそのまま反映される）**で管理し、別端末への引っ越しまで含めて安全に再現できるようにする。

- 設定の実体は本リポジトリ側に 1 つだけ置き、ホームからは一方向のシンボリックリンクを張る（合意済み）。
- 配置と検査は、chezmoi の設計を参考にした自前ツール（Bun + TypeScript、新規実装）が担う。
- 既存の開発環境（mise / uv / Go / Rust / Git / Docker、Starship の見た目）を壊さず、段階的に移行する。

## 2. 対象

| 利用者 | 得られるもの |
|---|---|
| 本人（WSL 利用者） | 設定の一元管理、別端末への引っ越し、視覚的な設定（TUI）とスクリプト可能な操作（CLI） |
| Agent（AI） | 作業規約（`AGENTS.md`）、前提知識（`.agent/skills/wsl-dotfiles`）、進捗の正本（`docs/task-list.md`） |

## 3. 機能要求

決定済みの要求（2026-10-19）。実装順序は未決定であり、設計文書で確定する。

| 機能 | 内容 |
|---|---|
| 配置の中核 | 対応表に基づく symlink 配置、検査・状態表示。既存ファイルがあれば停止し、バックアップ付きの移行は別操作とする。一時 HOME で試験してから実環境へ適用する |
| テンプレート | 端末差分（名前・メール等の変数）で内容を出し分ける。テンプレート対象はリンクではなく生成物になるため、対象の切り分けと編集導線を設計で決める |
| 変更時スクリプト | 設定変更時などにだけ走るスクリプト。前回実行内容の状態はリポジトリの外（ローカル）に置く |
| 引っ越し | 新端末で clone から初期設定（端末固有設定の作成、配置計画の確認、適用、初期構築）までを案内する |
| 暗号化保存 | 暗号化して保存したいものを暗号文としてリポジトリに置けるようにする（age 形式を想定、復号鍵はリポジトリ外）。**SSH 秘密鍵は対象外**とし、端末ごとに作り直して公開鍵を登録する運用とする |
| CLI | 全機能をコマンドラインで操作できる（端末なし・自動実行でも動くフォールバック） |
| TUI | Web ページのように視覚的に設定できる画面。CLI と同じ設定ファイルを編集し、同じ中核を使う。技術選定は試作で確かめてから確定する |

zsh の構造と独自コマンド `gg` は参照リポジトリ `shiratama644/UbuntuHome` の構造・操作感を参考にする（取り扱いの詳細は未決定）。

## 4. 非目標

- chezmoi 本体との互換性（設計の参考に留め、コードの複製もしない）。
- 秘密情報の平文保存。SSH 秘密鍵の引っ越し（暗号化を含む）。
- Starship の見た目や既存ツール構成の変更。
- ホーム全体や履歴ファイルの Git 管理。

## 5. 用語

| 用語 | 意味 |
|---|---|
| 実体 | 本リポジトリ側にある設定ファイルそのもの（Git 管理対象はこれだけ） |
| 対応表 | リポジトリ内パスとホーム側パスの対応を明示する表（形式は未決定） |
| 配置（deploy） | 対応表に従ってリンク作成・生成を行うこと |
| 検査（check） | リンク切れ・通常ファイル化・想定外リンク先・構文などを調べること |
| 生成物 | テンプレートから作られる実ファイル。リンクと違い、編集しても差分にならない |
| 端末固有設定 | リポジトリの外に置くローカル専用の値（名前・メール・復号鍵の場所など） |
| 中核 / CLI / TUI | UI なしの頭脳部分 / コマンドラインの操作面 / 画面の操作面 |
