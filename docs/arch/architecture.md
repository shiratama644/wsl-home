## 2. 責務の分担

| 対象 | 役割 | 変更頻度の目安 |
|---|---|---|
| `AGENTS.md` | 「どう作業するか」の規約。常に正 | 低（方針変更時） |
| `.agent/rules/` | 「いつ・どのファイルで何を守るか」の詳細 | 低 |
| `.agent/skills/` | 前提知識と「どうやるとうまくいくか」 | 中 |
| `.agent/hooks/` | トリガー別の定型手順・自動チェック | 低 |
| `docs/task-list.md` | 進捗と証拠の正本 | 高（タスクごと） |
| `docs/arch/` | 仕様・構成 | 中 |
| `docs/adr/` | 個別の設計判断と理由 | 追加のみ |
| `docs/planning/` | 個別タスクの計画 | 高（タスクごと） |
| `.agent/logs/` | 実行の事実の記録。書き換えない | 追加のみ |

同じ内容を複数箇所に書かない。作業手順は `AGENTS.md`、詳細ルールは `rules/`、前提知識は `skills/`、仕様は `docs/arch/`、進捗は `task-list.md` を正とする。

## 3. 自前ツールの構成方針（決定済みの方針のみ）

- 頭脳（設定の読み込み・配置計画・検査・適用）を UI なしの中核に寄せる。
- CLI は全機能を持ち、端末なし・自動実行でも動く（フォールバック）。
- TUI は CLI と同じ設定ファイルを編集し、同じ中核を使う。TUI 側にしかない設定経路を作らない。
- 端末固有の値と実行状態（変更時スクリプトの前回内容など）はリポジトリの外（ローカル）に置く。
- 暗号化の復号鍵はリポジトリの外に置く。SSH 秘密鍵は暗号化保存の対象にしない。

技術選定（TUI の部品、テンプレート方式、対応表の形式など）は設計文書で確定する。

## 4. Agent が情報を読み込む流れ

1. **セッション開始・指示受領時**: `git status`・現在のブランチ・直近のコミットを確認する（`hooks/session-start.sh`、`hooks/pre-task.md`）。未完了の把握は `docs/task-list.md` の未完了サマリー。
2. **作業規約の確認**: `AGENTS.md` を読む。プロジェクト固有の検証手段は §6.1 を参照。
3. **知識の選択**: `.agent/skills/index.md` の「読み方ガイド」から必要なスキルだけを読む。dotfiles 設計では最初に `wsl-dotfiles` を読む。
4. **編集時**: 編集禁止領域と機密ファイル混入・目次更新漏れをフックで確認する。
5. **完了時**: 検証を実行し、証拠を `task-list.md` に記録し、`.agent/logs/` に実行ログを残す。

## 5. 変更の原則

- 構成を変えたら、本ファイル・`docs/README.md`・`README.md`・`AGENTS.md §8` を同じ変更で更新する。
- フックのスクリプトは POSIX `sh` で書き、終了コード（0 = 許可、2 = ブロック）の規約に従う。
- 環境に依存する制約（サンドボックスと実環境の区別など）は `AGENTS.md §6` に書く。
